# Demo Supplier Seed Data

These ten suppliers are synthetic fixtures for local or non-production testing.
Their company identifiers, contacts, bank accounts, payment verification, and
integration settings are not real and must not be used for actual payments.

Run `npm run prisma:seed:suppliers` to insert or refresh the fixtures. The command
uses the `DATABASE_URL` configured for this environment and refuses to seed when
`NODE_ENV=production`. It is idempotent. The seed sets participant status to
`ACTIVE`, payout status to `VERIFIED` using the `SEED_DEMO` method, and creates
an active `sandbox` integration for each supplier. This is simulated seed state,
not actual bank-account verification or a connection to a payment provider.

API key and secret values are deterministic test credentials generated by the
seed and deliberately omitted from this document. Never use them outside a
non-production environment. The seeded records do not create user accounts.

## List suppliers through the API

Use `GET /supplier/directory` to retrieve registered suppliers. The endpoint
requires a PayAssure user access token from `POST /auth/login` (or a refreshed
token from `POST /auth/refresh`). A supplier session token from
`POST /supplier/authenticate` is not used for this endpoint.

### Request

```http
GET /supplier/directory HTTP/1.1
Host: localhost:3000
Authorization: Bearer YOUR_ACCESS_TOKEN
Accept: application/json
```

There is no request body or query parameter. For example, using `curl`:

```bash
curl --request GET \
  --url "http://localhost:3000/supplier/directory" \
  --header "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  --header "Accept: application/json"
```

Any active authenticated user may call the endpoint; no administrator role is
required. Without a valid access token, the API returns `401 Unauthorized`.

### Response

On success, the endpoint returns `200 OK` with JSON. The `count` is the number
of supplier records returned, and `suppliers` is sorted by business name. This
example shows one record; the demo seed in this document creates ten:

The seeded suppliers use the same contact and payout phone number,
`0791614036`. `merchantId` is `null` when the supplier has no
integration. `integration` and `payment` are also `null` when those details are
not configured. For M-Pesa payouts, the payment `phoneNumber` is masked; for
bank payouts, the `accountNumber` is masked and `bankCode` or `shortcode` may be
included. Integration API keys, API secrets, payment activation secrets, and
full payout identifiers are never returned. See [the API endpoint reference](./API_ENDPOINTS.md)
for the endpoint contract.
